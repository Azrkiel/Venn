Venn · Code reference

One answer. Shared overlap.

Venn lets an organizer share a planning link. Friends mark when they are available, and the group sees where their answers overlap. The separate calendar planner can suggest times from consenting Google calendars.

This is a reference route through the implementation, not a record of a completed learner walkthrough or real-phone trial. It works offline without scripts or external resources.

Follow “Save availability”

1. Choose and saveName and selected date/time ranges leave the browser only when the participant saves.
→
2. Validate and storeThe API checks the request. A transaction saves one response per browser identity and poll.
→
3. Show the overlapThe response includes aggregate counts and this browser's own answer. Other visible pages refresh every five seconds.

If saving fails, the form keeps the edits and displays an error. Once voting closes, the server rejects changes while retaining readable results. An empty selection is an explicit unavailable response.

A three-stop reference route

  1. Input and visible confirmation

    src/app/r/[share]/availability-voting.tsx — search for AvailabilityVoting and async function save.

    The component collects a name and selection, obtains a browser guest key and sends a PUT. It shows “Saved” only after a successful response. The same component restores edits and renders live counts.

  2. The HTTP boundary

    src/app/api/venns/[share]/availability/route.ts — search for PUT.

    The route checks same origin, rate limits and validates JSON. It prefers the existing HTTP-only guest cookie, calls the service and returns a private, uncached response. A display name is never authentication.

  3. Persistence and overlap

    src/features/availability/service.ts — search for saveAvailability and view.

    A serializable transaction checks closure and saves the answer. aggregateAvailability calculates counts from the saved ranges. The public view omits other people's individual ranges and calendar data.

The other pieces

Creation, identity and storage

src/app/venn/create-venn.tsx collects the plan. create-venn-draft.ts validates a tab-scoped draft so signup can return to it. Creating the actual poll still requires an authenticated account. src/auth.ts handles sign-in; prisma/schema.prisma defines persisted records.

Private calendars and suggested replies

src/features/calendar/ handles separate OAuth consent, encrypted grants and free/busy queries. src/features/scheduling/intent.ts interprets an ask through Gemini; rank.ts ranks time windows deterministically. A failed calendar stays unknown. Availability-poll busy overlays are viewer-only and do not vote for someone.

Phone delivery and explicit calendar writes

src/features/messaging/bot.ts authenticates Photon webhooks and handles paired-organizer commands. src/features/availability/notices.ts delivers closed-poll summaries. src/features/requests/add.ts and booking.ts check explicit owner writes, conflicts and duplicate prevention. No shared availability answer automatically books an event.

A practice to reuse

Make success depend on observed completion. Venn's save button acknowledges success only after the server accepts the response. tests/e2e/ui-polish.spec.ts holds the save request to check the pending state, then separately tests success and failure with edits preserved. For another app, test the waiting and failure paths as deliberately as the successful click.
